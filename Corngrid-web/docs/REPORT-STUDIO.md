# Report Studio

The admin and user Overview pages include a shared Report Studio. It uses the CornGrid Brand Report visual system and the original user-supplied logo; `public/images/corngrid-report-logo.png` must remain unchanged (SHA-256 `7506b1ae01aff0a3c7e25cfc2c9b06a08cb4d645e224217e32fa3e22c0dd93a0`).

The studio starts collapsed on every page load. Its native dropdown button exposes `aria-expanded` and `aria-controls`, supports Enter/Space, and opens/closes the full panel. Report data is first requested on opening. Closing retains the selected filters and preview while pausing automatic refresh; reopening preserves that work.

“Share image” always opens a CornGrid sharing dialog with image preview, editable caption, “Share to apps”, “Download image” and “Copy caption”. PNG/File preparation finishes during report generation, before sharing is enabled. The native share call runs directly from the second button's click without asynchronous image encoding first, preserving transient user activation. Unsupported browsers, blocked shares and cancellations leave visible download/copy choices; they never silently download on opening the popup. Image downloads use an attached anchor so the existing Android blob-save bridge can intercept them. The preview is frozen while either sharing dialog is open. No image is publicly uploaded just to use social sharing.

[MDN's navigator.share documentation](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share) documents transient activation, permission failures and limited file-sharing compatibility (including Android WebView). Available apps are controlled by the device. Existing Android builds without Web Share support use the explicit download/copy flow; a web update cannot add an OS share API to an installed WebView.

Admin templates are listed below; user reports include own account performance, own sandbox status and Partner Report for active partners. Statistical reports support daily, Monday–Sunday weekly, calendar monthly and calendar yearly periods. Select any date within a period, the reporting timezone, currency, account scope and portrait/story/landscape size. The current calendar period is bounded by generation time and labeled “period to date”. Past-period fund values use the latest snapshot received inside that period; they never substitute today's balances for historical data.

## User reports

Account performance and Sandbox status are available to signed-in users. Partner Report is included in authenticated options only when the user has an active `partner_profiles` record and is not archived. Generation checks eligibility again, so suspended/non-partner users cannot bypass the selector with a direct request. Pending partner applications do not qualify. Reload Overview after partner approval to refresh the available choices.

Partner reports support all four periods and three PNG sizes. They show approved commissions (including paid commissions), pending commissions, actual paid payouts, commission record counts, current published strategies and current total strategy submissions. Commissions use creation dates and current status; rejected/cancelled records are excluded. Payouts use `paid_at`, not requested dates or commission creation dates. Payouts and commissions must never be added together. Non-deleted strategy counts are explicitly current snapshots even for past periods.

Partner currency comes from that user's ledger currencies, independent of MT5 accounts; MYR is the schema default when no ledger rows exist. No conversion occurs. An unfiltered multi-currency API request returns N/A for monetary values until a currency is selected. Known empty ledger sums are zero; absent MT5 history remains N/A. Partner IDs, customer information, bank details and payout references are omitted from reports. Queries read only the session owner's `partner_transactions`, `partner_payouts` and `ea_submissions`. No schema change is needed.

Download PNG, Share image, Share to live feed and Export data work with all user report types. Feed publishing still requires explicit review and confirmation. The blank-content editor remains admin-only.

## Administrator templates

The admin-only Template selector contains seven choices, separate from period and image size:

| Template | Composition and data |
|---|---|
| Platform Growth | Editorial registered-user figure, period registrations, chart and dark KPI panel |
| Sandbox & Infrastructure | Editorial total/fresh-running figures, white creation chart and one dark status panel |
| Total Account Funds | Black balance figure, a small yellow equity highlight, white comparison chart and one dark fund KPI panel |
| Client Performance | Black net P/L figure, highlighted win rate, white received-deal chart and one dark statistics panel |
| Subscription Snapshot | Black subscriber figure, highlighted expiry count, white activation chart and one dark status panel |
| Milestone Announcement | Select a verified metric for the editorial headline figure, with a white activity chart and three supporting figures in one dark panel |
| Blank CornGrid Template | Official header/footer/theme with an empty body; optional title, subtitle, highlighted text, body and byline |

All seven reuse the original logo and header/footer coordinates. User accounts have their own report choices; the blank editor remains admin-only and the user API rejects every admin type. Subscription counts exclude deleted records/archived users; current status and period starts remain distinct. Active subscriptions do not assert verified payment, revenue or renewal counts. Milestones describe an observed metric, without inventing a threshold or growth percentage.

The shared admin and user design follows the user-supplied original growth infographic: warm off-white `#F8F6EF`, black number-led headlines, a restrained `#FFEB00` text highlight, white rounded chart card with a fine border, and a single charcoal `#1B1B1B` KPI panel. The first KPI uses yellow; other values are white. Charts label values, axes, latest periods and currency comparisons; counts use integer ticks and absent data remains N/A. Neutral editorial headlines introduce the source data without inventing achievements. Blank documents place their text directly on the same paper with an inline yellow highlight. Portrait, Story and Landscape preserve this palette and hierarchy. User account, sandbox and partner reports use this same editorial layout and original header/footer.

Blank documents use `mode: manual`, an explicit admin-authored footer, no statistics and no chart. GET returns an empty skeleton after existing admin authentication; it does not read or write database records. Content is edited/rendered locally, preserves paragraphs, remains in the form when switching templates, and updates after a short typing pause. It is not saved to a server or claimed as verified platform data. Draft content lasts only in the current page session. An entirely empty editor exports just the branded header and footer. Long text fails visibly instead of being cropped; choose Story or shorten it. Period and auto-refresh controls are hidden for blank documents; the date/timezone still appear in the shared header/footer. The cached blank skeleton avoids a server request on every keystroke. Existing download, social sharing and deliberate feed publishing are available for generated custom images too.

GET `/api/reports/options` and `/api/reports` require the existing user session. Admin equivalents are `/api/admin/reports/options` and `/api/admin/reports`, protected by the separate existing administrator session. Query parameters: `type`, `period`, `date` (YYYY-MM-DD), `timezone` (IANA), optional `accountId` and `currency`. Users cannot override their session's owner. Administrator account options list the latest 500 accounts; “all available accounts” includes the whole permitted scope.

The API executes SELECT statements against existing tables; no migration or scheduler is needed. No revenue, return percentages or opening balances are inferred. Archived users are excluded. Account funds are grouped by the selected currency; there is no exchange-rate conversion. Counts are counts of received records; zero received deals means N/A for monetary results and win rate. Net closed P/L requires both commission and swap. No received point means a chart gap, not an invented zero P/L. Current sandbox counts are explicitly distinct from historical uptime; a running instance needs a recent heartbeat. Current platform KPI totals and period registration charts are labeled separately. History is limited by the existing MT5 data retention policy.

`report-service.js` supplies dated, source-labeled data. `report-renderer.js` renders the official logo, editorial header, chart, six KPI cards and date/source footer directly to canvas without external services. The UI provides an accessible equivalent of the chart and every number beside the image. PNGs are 1080×1350, 1080×1920 and 1920×1080. Sharing offers a device share menu where supported and explicit image-download/caption-copy choices elsewhere. JSON export includes exact received values, notes and timestamps. Preview refreshes every 60 seconds while visible and pauses during sharing review. Changed filters invalidate export buttons until the new report is generated.

Publishing requires clicking “Share to live feed”, reviewing the frozen image/caption and clicking “Publish report”. It uses existing authenticated upload endpoints, post ownership validation, rate limits and quotas. Admin posts are announcements; user posts are community posts. Generation itself does not publish anything. Shared images omit account numbers, account names, usernames, emails and credentials. Financial values remain visible to the user in the publishing review. This is an observation report, not an audited statement or a claim of complete broker history.

Validate with `node --test test/reports.test.js` and the existing feed/session tests. Browser preview must use an isolated test database, not `server.js` with the production .env. Production rollout needs the report modules, public report files/logo, Overview changes, route registration in server.js, the service-worker asset entries and the specific report asset paths in the root IIS web.config rewrite rule. Restart the website process through its existing service manager. No sandbox node or trading terminal restart is required. `marketing/deploy-user-partner-reports.ps1` backs up the six changed website files, refuses unrelated differences, checks live PostgreSQL in a read-only transaction and verifies authenticated live APIs and asset hashes. Verification failure restores the previous files and restarts the website.
