# CornGrid Android App (Capacitor 8)

CornGrid ships as a native Android application that wraps the **existing live web
platform** at `https://corngrid.com`. Nothing about the product was rebuilt: the
Express 5 + SQLite backend, cookie/Bearer authentication, dashboard, market data,
uploads and downloads all run exactly as before inside a hardened WebView. The
Capacitor layer only adds what Android expects of a native app (launcher icons,
splash, back button, offline UI, downloads, system-bar handling).

| Item | Value |
| --- | --- |
| Application ID | `com.corngrid.app` |
| App name | CornGrid |
| Capacitor | 8.5.3 (`core`, `cli`, `android` + `app`, `splash-screen`, `status-bar`, `network`, `browser`) |
| Min / Target / Compile SDK | 24 / 36 / 36 |
| Version | `versionCode 1`, `versionName 1.0.0` |
| Server | `https://corngrid.com` (remote WebView, HTTPS only) |
| webDir | `web-app-shell/` (minimal placeholder — keeps `public/uploads` and site assets out of the APK) |

## 1. Prerequisites

1. **Node.js ≥ 20.17** (matches `engines` in `package.json`).
2. **JDK 21** — e.g. Temurin, extracted under
   `%LOCALAPPDATA%\Android\jdk-21\jdk-21.0.12.1+1`.
3. **Android SDK** with:
   - `platforms;android-36`
   - `build-tools;36.0.0`
   - `cmdline-tools` (at `Sdk\cmdline-tools\latest`)

   Install missing pieces with:

   ```bat
   sdkmanager --sdk_root=%LOCALAPPDATA%\Android\Sdk "platforms;android-36" "build-tools;36.0.0"
   ```

4. Environment variables (PowerShell):

   ```powershell
   $env:JAVA_HOME    = "$env:LOCALAPPDATA\Android\jdk-21\jdk-21.0.12.1+1"
   $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
   ```

   Android Studio users can instead set the IDE's Gradle JDK to 24+ JDK 21 and let
   Studio manage `sdk.dir` through `local.properties`.


`android/` is generated by `npx cap add android` but **contains deliberate local
modifications** (MainActivity, theme, manifest, drawables) — do not regenerate it
without re-applying those changes. All modified/new files are listed in §7.

## 3. Building

```powershell
cd Corngrid-web
npx cap sync android             # copies config + web-app-shell, updates plugins
cd android
.\gradlew assembleDebug          # -> app\build\outputs\apk\debug\app-debug.apk
```

Install on a connected device/emulator:

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## 4. Release signing

The release build is assembled unsigned by default. To sign it:

```powershell
keytool -genkeypair -v -keystore corngrid-release.jks -keyalg RSA `
  -keysize 2048 -validity 10000 -alias corngrid

cd android
.\gradlew assembleRelease        # -> app\build\outputs\apk\release\app-release-unsigned.apk

$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
& "$env:ANDROID_HOME\build-tools\36.0.0\apksigner.bat" sign `
  --ks corngrid-release.jks --ks-key-alias corngrid `
  --out app\build\outputs\apk\release\app-release.apk `
  app\build\outputs\apk\release\app-release-unsigned.apk
```

Keep the keystore and its passwords out of version control (`.gitignore`
already excludes `*.jks`, `*.keystore`, `keystore.properties`).

## 5. Configuration reference (`capacitor.config.json`)

| Key | Value | Why |
| --- | --- | --- |
| `server.url` | `https://corngrid.com/login` | Opens the portal directly; an existing session cookie redirects straight to the dashboard. |
| `server.allowNavigation` | `corngrid.com`, `*.corngrid.com` | Only CornGrid hosts render inside the app; every other URL is handed to the external browser (`Bridge.launchIntent`). |
| `server.cleartext` / `android.allowMixedContent` | `false` / `false` | HTTPS-only; mixed content blocked. |
| `android.webContentsDebuggingEnabled` | `false` | DevTools cannot attach to the WebView (no remote inspection of sessions). |
| `android.loggingBehavior` | `none` | No Capacitor logging from the release app. |
| `android.backgroundColor` | `#080a0f` | Brand background behind transparent web content. |
| `plugins.SplashScreen` | 1200 ms, auto-hide, no spinner | Short branded splash; the page itself provides loading UI (gold progress bar). |
| `plugins.SystemBars` / `plugins.StatusBar` | `style: DARK` | White status/gesture icons on the dark background (Capacitor renders `DARK` as *light-content* icons). |
| `plugins.App.disableBackButtonHandler` | `true` | Disables Capacitor's default back handler so `MainActivity` is the single, unambiguous back-button authority. |

## 6. Native behaviors (`MainActivity.java`)

**Back button** — walks WebView history; at the app root it *minimizes*
(`moveTaskToBack(true)`) instead of exiting: an accidental press never kills the
session, and the user is never trapped (launcher/recents always work).

**Loading state** — a 3 dp gold progress bar is pinned to the top of the window
and tracks `WebView.getProgress()`.

**Offline / server errors** — a full-screen branded overlay
(`res/layout/cg_offline_overlay.xml`: logo, explanation, gold *Try again*
button) is shown when

- the device's default network drops (`ConnectivityManager.registerDefaultNetworkCallback`),
- the main frame fails to load with a real network error, or
- `corngrid.com` answers with HTTP ≥ 500.

Sub-resource failures (fonts, images) are filtered via `isForMainFrame()` and
never trigger the overlay. When connectivity returns the page **reloads**
automatically so trading data is re-fetched instead of presenting stale values —
the backend also serves HTML with `Cache-Control: no-store` and the service
worker uses network-first for navigations, so nothing stale can masquerade as
live.

**Downloads**

- *Plain `http(s)` file links* (PDF/archives): `DownloadListener` → system
  `DownloadManager`, with the session `Cookie` and `User-Agent` attached and the
  notification visible until completed. API ≥ 29 writes to the public Downloads
  collection; API 24–28 uses the app-specific external dir (no storage
  permission required in either case — no `WRITE_EXTERNAL_STORAGE` at all).
- *Authenticated blob downloads* (preset `.set` files, setup-guide PDF, trade
  CSV exports): the site does `fetch(...) → blob → a[download].click()`, which a
  system download manager cannot see. `MainActivity` injects a small hook on
  every page start/finish (via `evaluateJavascript` — the site's own source is
  never modified) that intercepts `a[download]` clicks on `blob:` URLs — both
  real taps and programmatic `link.click()`, including the detached anchor the
  CSV exporter uses — fetches the blob in-page and passes base64 to the native
  `window.CornGridBridge.saveBlob()`, which writes it through `MediaStore.Downloads`
  (API ≥ 29) or the app-specific dir (older). Files land in Downloads and a toast
  confirms the name. Current files are all well under 2 MB, comfortably inside
  the JS-bridge's practical payload range.

**Uploads** — handled natively by Capacitor's `BridgeWebChromeClient`
(`onShowFileChooser`); the feed image picker works unchanged.

**Crash recovery** — if the WebView renderer process dies,
`onRenderProcessGone` shows a message and recreates the activity instead of
leaving a blank window.

**Viewport / edge-to-edge (targetSdk 36)** — every page previously declared
`viewport-fit=cover`. Capacitor 8's `SystemBars` passes system-bar insets
*through to the WebView* (instead of padding the window) whenever the WebView is
≥ 140 **and** the page declares `viewport-fit=cover` — which would have rendered
page headers underneath the status bar, because the site only uses `env()`
insets at the bottom. The `viewport-fit=cover` declaration was therefore removed
from all served pages (`public/*.html`, `web-app-shell/index.html`, and the root
`Website/index.html`). On browsers/PWAs this changes nothing visible (content
was already inside the safe area there); in the app it makes Capacitor apply
native window padding on **every** WebView version, so headers, dashboard nav
and the bottom navigation bar are always clear of system bars. The site's
existing `env(safe-area-inset-bottom)` floors (`max(...)`/`calc(...)`) continue
to resolve harmlessly.

## 8. Regenerating launcher / splash assets

```powershell
cd Corngrid-web
npm run gen:android-assets
```

The script reads `public/images/pwa-512.png` and rewrites every launcher icon
(legacy rounded-square + circle, adaptive foreground at 66% inside the 108 dp
safe zone) and all eleven `splash.png` files (dark `#080a0f` canvas with a
rounded gold logo tile at 42% of the shorter side) **at each file's existing
pixel dimensions**. It is idempotent.

## 9. Verification performed

- **Backend:** `npm test` → 12/12 passing.
- **Web regression (Playwright, local server):** `/` and `/login` render at
  390 × 844 with zero horizontal overflow, no `viewport-fit` anywhere, login
  form + button present; the only console errors are the expected
  `401 /api/me` and `401 /api/admin/overview` probes when signed out.
- **Device (Android 15 / API 35 x86_64 emulator):** the debug APK was installed
  (`adb install`), launched (`am start`), and reached the foreground
  (`mCurrentFocus = com.corngrid.app/.MainActivity`, process alive). Pixel
  analysis of on-device screenshots confirmed the critical native behaviors:
  the **branded splash** renders exactly (`#080a0f` canvas with the centered
  gold logo tile), the edge-to-edge **status-bar strip is brand dark** — no
  white strip, no header overlap (validating the `viewport-fit=cover` removal +
  dark `windowBackground`), **white status/gesture icons** on dark
  (`plugins.SystemBars style: DARK` working), and the bottom gesture area stays
  clear. Caveats: the headless emulator (software/ANGLE GPU, Play image)
  repeatedly ANR'd *system* components (system, SystemUI, launcher — the
  CornGrid app itself never ANR'd) and later screen captures returned black
  frames; the live-page render, on-device back-button and offline-overlay
  checks should be repeated on a hardware-accelerated device. The AVD also
  needs ≥ 8 GB of free disk for its data partition (this machine's C: drive had
  4.3 GB, so the AVD was relocated to `D:\AndroidAVD`).
- **App (build):** `npx cap sync android` clean (5 plugins); Gradle `assembleDebug`
  → **BUILD SUCCESSFUL** producing
  `android/app/build/outputs/apk/debug/app-debug.apk` (4,329,651 bytes).
  `aapt dump badging` confirms: package `com.corngrid.app`,
  `versionCode 1 / versionName 1.0.0`, `minSdk 24 / targetSdk 36 /
  compileSdk 36`, label **CornGrid**, launcher activity
  `com.corngrid.app.MainActivity`, permissions limited to `INTERNET` and
  `ACCESS_NETWORK_STATE` (plus Capacitor's internal dynamic-receiver
  permission).

## 10. Known limitations / notes

- **No push notifications.** The backend has no FCM integration, so none was
  faked in the app. To add it later: create an FCM project, drop
  `google-services.json` into `android/app/` (the Gradle script already
  applies `com.google.gms.google-services` when the file exists and logs a
  harmless info line when it does not), add a server-side send endpoint, and
  register tokens. No such file or secret is committed today.
- **Blob downloads > ~2 MB** would need chunking through the JS bridge; every
  current file (presets, guide PDF, CSV exports) is far below that.
- **API 24–28 download location:** without `WRITE_EXTERNAL_STORAGE` (deliberately
  not requested) blob/DownloadManager files go to the app-specific external
  directory rather than the shared Downloads collection. API 29+ uses the public
  Downloads collection normally.
- **Production auth:** the app points at live `https://corngrid.com`, and no
  automated login was run against production (all automated auth tests ran
  against the local server). Smoke-test sign-in manually on a device.
- `disableBackButtonHandler` means site JavaScript would not receive Capacitor
  `backButton` events if it ever starts listening for them — currently no site
  code does (verified).

## 11. Troubleshooting

| Symptom | Fix |
| --- | --- |
| `compileSdk version 36 not found` | `sdkmanager "platforms;android-36" "build-tools;36.0.0"` (§1). |
| Gradle uses the wrong JVM / `Unsupported class file major version` | Export `JAVA_HOME` to the JDK 21 path before `gradlew`. |
| Local server returns stale HTML | Restart `node server.js` — the test server reads from disk, but an old process may still hold the port. |
| `Execution failed for :app:mergeDebugResources` after re-adding the platform | Re-run `npm run gen:android-assets` — `npx cap add android` overwrites `res/` with stock art. |
| Emulator: `x86_64 emulation requires hardware acceleration` | Enable Windows Hypervisor Platform (or Hyper-V) and reboot. |
